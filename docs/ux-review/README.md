# UX/UI-ревью · 10 сентября 2026

Проверка опубликованного сайта, Chromium, 1280×720 и 390×844. Наблюдения из браузера; исходный код на этапе проверки не читался.

## ISSUE-001 · medium · Главная: первое действие ниже первого экрана
На 1280×720 вводный блок занимает экран; сетка букв ещё не видна. Призыв «Нажми на готовую букву» не сопровождается переходом к сетке. Справа показан холст Я без понятного объяснения счётчика. Это гипотеза о затруднении первого визита, а не измеренная потеря пользователей.
Доказательство: screenshots/home-wide.png. Открыть главную на указанной ширине. Видео не требуется.
Предложение: явный переход «Выбрать букву ↓» и короткая подпись «Я — общий холст участников»; отдельное действие для последней опубликованной буквы.

## ISSUE-002 · medium · Полигон Л: большая дистанция между сценой и параметрами
На 390×844 сцена начинается около y=240, заканчивается y=605; параметры начинаются около y=738. Пустое пространство разносит взаимосвязанные элементы. Доказательство: screenshots/lab-l-mobile.png. Открыть lab/l.html. Видео не требуется.
Предложение: на телефоне поток «режим → сцена → параметры», без растягивания вертикальных промежутков.

## ISSUE-003 · medium · Полигон Л: выбор из 17 режимов плохо обозрим
На телефоне видны первые пять кнопок и край следующей. Счётчик 03/17 расположен внутри сцены; полного списка рядом с выбором нет. Горизонтальная прокрутка есть, но искать далёкий режим неудобно. Доказательство: screenshots/lab-l-mobile.png. Видео не требуется.
Предложение: сохранить полосу, добавить кнопку полного списка с текущим номером; в списке показать все названия и выбранную механику.

## ISSUE-004 · medium · Полигон: мелкие цели касания
Кнопки режима и общих действий имеют высоту 29.94 CSS px на 390×844; плотный ряд затрудняет точное касание. Это рекомендация удобства, не заявление о несоответствии стандарту. Доказательство: screenshots/lab-l-mobile.png, размеры DOM измерены в браузере.
Предложение: зона нажатия 44 px на устройствах с грубым указателем; сохранить компактный вид на компьютере.

## ISSUE-005 · low · Каталог: количество механик обозначено голой цифрой
В правом нижнем углу клеток стоят 1, 4, 17 и т.д.; без подсказки неясно, что это число вариантов. В доступном имени ссылки также просто число. Доказательство: screenshots/labs-wide.png. Открыть lab/index.html. Видео не требуется.
Предложение: короткая общая легенда «цифра в клетке — число механик» и полное доступное имя ссылки. Не заполнять плитку текстами механик.

## ISSUE-006 · high · Х: Tab переключает панель, не перемещая фокус
Вход с клавиатуры: сфокусировать «Буква Х, готово», Enter. Фокус попадает на крестик. Tab раскрывает панель, следующий Tab скрывает её, следующий снова раскрывает. Фокус остаётся на крестике; ползунки обычной последовательностью Tab недостижимы. Повторено дважды.
1. Открытая Х, панель скрыта: screenshots/tab-1.png.
2. Нажать Tab: screenshots/tab-2.png.
3. Нажать Tab ещё раз: screenshots/tab-3.png.
Видео не удалось собрать: agent-browser сообщил об отсутствии ffmpeg. Скриншоты последовательности сохранены.
Предложение: сохранив принятый Tab-шорткат, при открытии переводить фокус на первый контрол панели; внутри всей панели разрешать обычную Tab-навигацию, включая кнопки. При закрытии возвращать фокус на toggle. Проверить Shift+Tab и Esc.

## Дополнительные рекомендации (не подтверждённые ошибки)
- Х на телефоне остаётся квадратным окном около 358×358 посреди экрана. Для рисования рассмотреть режим «на весь экран» с явным возвратом; не включать автоматически для всех букв.
- Подсказку «i» дополнить коротким действием при первом входе («тяни линии»); длинное описание оставить свёрнутым.
- «Текст» в полигоне переименовать в «Как играть» / «О механике» по содержимому. Принцип свёрнутой по умолчанию заметки сохранить.
- Состояния «на рекорд» / «песочница» и результат унифицировать визуально, не меняя правила начисления.
- Сохранять выбранную механику в URL и работу file://; каталог не превращать в ленту карточек с длинными описаниями.

## ISSUE-007 · medium · Старый полигон Б: значения ползунков не видны
Подписи «темп», «крупные», «мелочь» не содержат текущих значений. Настройку сложно запомнить или передать другому человеку. На новом каркасе Л значения уже показаны, поэтому это ещё и несогласованность двух поколений полигонов.
Доказательство: screenshots/lab-b-mobile.png. Открыть lab/b.html на 390×844. Видео не требуется.
Предложение: при работе над старым полигоном добавить значения в подписи по принятому в проекте паттерну. Не мигрировать все семь старых страниц одним большим изменением.

## Направления формы

Интерактивное сравнение: [index.html](index.html).

1. **Бережная редактура** — существующая типографика и сетка, заметный переход к алфавиту и объяснение Я. Минимальный риск. Рекомендация для сайта.
2. **Буква дня** — главная как вход в последний опубликованный скетч; календарная сетка остаётся ниже. Лучше для возвращающихся, но сильнее меняет композицию. «Последняя» определяется публикацией, а не только календарной датой.
3. **Мастерская** — для полигонов: сцена и настройки рядом на компьютере, последовательно на телефоне; раскрываемый полный список механик. Рекомендация для лаборатории.

Эскизы иллюстрируют структуру, не заменяют механику букв. Ветка добавляет только этот каталог, рабочие исходники не меняет. Нет публикации, сетевых записей и изменений начисления очков.

## Что проверено и пределы ревью

- Опубликованные главная, сетка, Х и её панель; каталог полигонов, Л на общем каркасе, Б на старом.
- Широкая раскладка 1280×720, узкая 390×844. В проверенных главной/Х/Л переполнение по горизонтали не наблюдалось.
- Л через file:// открылся, переключатели и параметры присутствуют; ошибок JavaScript инструмент не сообщил.
- Скриншоты со служебными красными рамками — аннотации инструмента, не оформление сайта.
- Нажатия мышью через CLI на главной не дали надёжного результата; клавиатурный вход проверен отдельно. Это не зарегистрировано как ошибка сайта.
- Это выборочное UX-ревью, не проверка всех 33 букв, всех механик и начисления результатов. Серверные операции и ввод имени не выполнялись.
- Реальный телефон и ручной touch-drag исходных игр не проверены. Узкий viewport не доказывает работоспособность касаний.
- 7 находок: 1 high, 5 medium, 1 low. Приоритет отражает влияние на взаимодействие; визуальные рекомендации не выданы за результаты пользовательского исследования.

## Проверка страницы предложений

`index.html` открыт в Chromium через file:// и локальный HTTP. Проверены переключение направлений, выбор варианта эскиза, изменение ползунка клавиатурой (150 → 151), смена фона и сброс. На 390×844 горизонтального переполнения нет; ошибок JavaScript инструмент не сообщил. Сам эскиз работает без сервера. Для переходов в основной сайт из эскиза используйте локальный HTTP, поскольку основной сайт загружает ES-модули.

Просмотр: запустить из корня проекта `python3 -m http.server 8765 --bind 127.0.0.1` и открыть http://127.0.0.1:8765/docs/ux-review/index.html.
