# Backend холста Я

Дата: 2026-08-28

## Цель этапа

Собрать первый вертикальный срез: участник получает очки, открывает кошелёк,
ставит свободную клетку, а состояние холста можно загрузить с другого клиента.
Основное приложение пока не подключаем.

## Зафиксированные решения

- Worker пишется без фреймворка и зависимостей, на стандартном `fetch` API.
- Хранилище — Cloudflare D1 `alphabet-wall`; Worker `alphabet-wall` опубликован
  только на маршруте `https://alphabet.pustota.link/api/*`.
- Токен участника — случайный UUID, он же `players.id`. Имена не уникальны.
- Токен передаётся в `Authorization: Bearer <token>`; для отладки допускается
  `X-Player-Token`.
- Уровень 0 — сетка 32×32, уровень 1 — 64×64, уровень 2 — 128×128.
- Площадь Я на уровне 0 фиксируем как 357 клеток; на каждом следующем уровне
  она увеличивается в четыре раза. Первая цифра (393) была снята до загрузки
  Manrope и заменена 2026-08-28.
- `scores.best_rank` хранит лучшее место за всё время. Без этого правило
  начисления за историческое продвижение не восстанавливается.
- `score_claims` хранит одно начисление на один запрос улучшения. Это позволяет
  сделать повторную отправку результата безопасной.
- Кошелёк ограничен по балансу: `earned - spent <= 10`; суммарный заработок не
  обнуляется при достижении потолка, излишек сгорает.
- Постановка клетки, списание очков и переход на следующий уровень выполняются
  одним D1 `batch()`.
- Суточный лимит отметок считается по токену и по хешу IP, в UTC.
- Пока у букв нет формализованных физических верхних границ, backend принимает
  результат в диапазоне `0..1_000_000`. Точные лимиты букв — следующий этап.
- Публичное состояние пока отдаёт имена участников, чьи отметки попали в ответ.
  Отдельный endpoint карточки клетки не вводим до проверки frontend-сценария.

## Срез 1

### Backend

- `GET /api/state`
- `POST /api/join {name}`
- `POST /api/score {letter, value}`
- `POST /api/mark {x, y}`
- CORS для локальной проверки и будущего same-origin подключения.
- Валидация тела, токена, координат, имени и результата.

### Не входит в срез

- подключение `wall.js` и `progress.js`;
- реальный домен Worker и боевой D1;
- точные верхние границы результатов букв;
- админская панель скрытия имён;
- rate limiting на уровне Cloudflare Rules/Turnstile.

## Порядок работ

1. Схема D1 и чистые функции валидации/начисления.
2. Worker API и атомарная постановка клетки.
3. Тесты правил кошелька, цены, уровня и начислений.
4. Развёртывание Worker и проверка `GET /api/state`.
5. Подключение frontend отдельным срезом.
