# Полигоны: общий каркас, перечень, правила

Дата: 2026-08-24

## Задача

Полигоны стали основным инструментом работы над буквой, но каждый собирается
копированием предыдущего. На каждую букву переносится ~200 строк CSS и 126–177
строк каркаса JS, которые потом расходятся между собой: в `yo` завёлся `onKey`,
в `z` — `pointer.pressure`, в `e` — индикатор звука и переключатель Е/Ё, и ничего
из этого не доехало до остальных. Версии в тегах скриптов дошли до `?24` — ручная
борьба с кэшем.

Нужно три вещи: страница-перечень полигонов, каркас, который делает полигон
удобнее, и правила, по которым новый полигон собирается не с нуля.

## Границы

Восемь существующих полигонов (`b`, `v`, `g`, `d`, `e`, `yo`, `zh`, `z`) **не
трогаем**. Они остаются на своём шелле и продолжают работать по прямым адресам.
Каркас обкатывается на новых буквах, начиная с И. Перевод старых — отдельный
заход, когда каркас докажет себя.

Следствие: живых плиток на перечне сначала не будет ни у кого. Механика плитки
строится сразу, но включается у полигона только когда он на новом шелле.

Общей библиотеки механик не делаем. Замер показал, что повторяется почти
исключительно каркас (`setMode`, `resize`, `renderTools`, `frame`, `track`,
`slot`, `num`, `on`); сверх него общего мало — `clamp`, `lerp`, `line`, `dot`,
`drawStatus`. Сами механики уникальны, и это правильно: буква участвует в
устройстве механики, а не служит контуром.

## Устройство

Три новых файла в `lab/` плюс страница перечня.

### `lab/lab.js` — каркас

Обычный скрипт, не модуль. Это решающий выбор: классические скрипты делят одну
глобальную область, поэтому файл буквы видит `S`, `ctx`, `num()` без импортов и
без параметров, и тела механик пишутся ровно так же, как пишутся сейчас. Модули
потребовали бы прокидывать контекст в каждый вызов `draw`/`step`.

`lab.js` грузится первым и сам подтягивает файл буквы: слаг берётся из имени
страницы (`zh.html` → `zh-lab.js`). На localhost к адресу дописывается
`?t=<время>`, в остальных случаях — фиксированная версия. Ручные версии в тегах
скриптов исчезают, грабли с кэшем закрываются.

**Что каркас определяет глобально:**

| Имя | Что это |
|-----|---------|
| `canvas`, `ctx`, `stage` | узлы сцены |
| `S`, `dpr` | сторона сцены в CSS-пикселях и плотность |
| `pointer` | `{x, y, px, py, down, seen, pressure}`, координаты в долях 0…1 |
| `modeState` | состояние режима, обнуляется при переключении |
| `variant` | текущий вариант буквы или `null` |
| `paused` | пауза |
| `INK`, `PAPER`, `MUTED`, `FAINT`, `GHOST` | цвета, переключаются вместе с фоном |
| `RED` | акцент, от фона не зависит |
| `STEP` | шаг физики, `1/60` |

**Помощники:** `clamp(v, min, max)`, `lerp(a, b, t)`, `slot(key)`, `num(key)`,
`on(key)`, `ink(a)`, `paper(a)`, `dot(x, y, color, radius = 0.008)`,
`line(x1, y1, x2, y2, color = INK, width = 0.008)`, `drawStatus(text, hot = false)`.
Координаты и размеры — в долях стороны, как в `z` и `zh`.

**Запуск:** файл буквы заканчивается вызовом

```js
startLab({
  title: 'Ж · шесть лучей',   // в шапку и в <title>
  modes: MODES,
  start: 'beetle',
  variants: ['Е', 'Ё'],        // необязательно
  globalTools: [...],          // необязательно, общие на все режимы
});
```

**Режим:**

```js
{
  label: 'жук',                // подпись кнопки
  note: 'что тут происходит',  // подпись в подвале
  tools: [...],
  cursor: 'crosshair',         // необязательно
  setup(), step(), draw(),
  onDown(e), onMove(e), onUp(), onKey(e, down), onTool(key), onVariant(v),
}
```

Обязательны `label`, `note`, `tools`, `draw`. Остальное по надобности.

**Инструмент** — одна из трёх форм:

```js
{ type: 'range',  key: 'legs',  label: 'ноги',   min: 2, max: 8, step: 1, value: 6 }
{ type: 'toggle', key: 'trace', label: 'след',   value: false }
{ type: 'button',                label: 'заново', action() {} }
```

Значения `range` и `toggle` живут под ключом `<режим>:<key>`, то есть у каждого
режима свои. Поле `global: true` снимает префикс — значение становится общим на
все режимы. После любого изменения каркас зовёт `mode.onTool?.(key)`.

### `lab/lab.css` — шелл

Всё, что сейчас лежит инлайном в каждой странице: токены, сетка `body`, шапка,
кнопки механик, сцена с крестиком и номером, подвал с инструментами и подписью,
мобильная раскладка. Плюс два новых состояния: `[data-ground]` на `body` и голый
режим.

### `lab/<буква>.html` — стаб

Побайтово одинаков для всех букв: ни заголовка, ни имени скрипта внутри —
`<title>` ставит каркас из конфига. Пятнадцать строк. Новый полигон = копия
стаба и файл с `MODES`.

## Что каркас даёт даром

**Состояние в URL.** `zh.html#beetle&legs=6&drag=0.3` — режим и ползунки текущего
режима, пишется через `replaceState`. Перезагрузка не сбрасывает настройку, к
удачному сочетанию можно вернуться и прислать его ссылкой. Ключ `bg` зарезервирован
под фон, инструмент так называть нельзя.

**Фон.** Кнопка и `KeyB` переключают `data-ground` между `paper` и `ink` — тем же
атрибутом, которым буква переключает фон на сайте. Сейчас полигон всегда бумажный,
а сцена на сайте по умолчанию тёмная, и это враньё: механику выбирают не на том
фоне, на котором она будет жить.

Переключение работает для кода, который берёт цвет из констант каркаса или из
`ink(a)`. Захардкоженные `rgba(22,22,22,…)` внутри механики так не перекрасятся —
отсюда правило: цвет только из констант.

**Клавиши** — по `event.code`, чтобы не зависеть от раскладки: `Digit1`…`Digit9` —
механика, `Space` — пауза, `Period` — один кадр, `KeyR` — заново, `KeyS` — снимок,
`KeyB` — фон. События из полей ввода пропускаются, как это уже сделано в буквах.

**Снимок PNG.** Канвас прозрачный — фон даёт CSS, поэтому прямой `toDataURL` даст
дырку вместо бумаги. Экспорт идёт через офскрин: заливка текущим фоном, поверх
канвас. Имя файла `<слаг>-<режим>.png`.

**Голый режим** `?bare` — прячет шапку и подвал, сцена занимает кадр целиком, без
рамки и номера. Нужен плиткам на перечне; составляется с хешем:
`zh.html?bare#beetle&legs=6`.

**Варианты буквы** — `variants: ['Е','Ё']` в конфиге: каркас рисует переключатель,
держит `variant` и зовёт `mode.onVariant`. Сейчас это есть только в Е и сделано
руками, но Ь/Ъ, И/Й, Ш/Щ попросят то же самое.

Индикатор состояния — только канвасный `drawStatus`. Так уже делают три полигона
из восьми, и это оставляет стаб универсальным: один механизм вместо двух.

## Перечень

`lab/index.html` — сетка карточек, данные из `lab/labs.js`:

```js
const LABS = [
  { slug: 'zh', letter: 'Ж', title: 'шесть лучей', date: '2026-08-23',
    mechanics: ['жук', 'изморозь', 'шарнир'], chosen: 'жук', tile: false },
];
```

Карточка целиком ссылка на полигон. Под названием — механики и какая уехала в
букву (или «ещё не выбрана»). В шапке — счётчик вида «8 полигонов из 33 букв».

При `tile: true` внутрь карточки становится `<iframe src="<slug>.html?bare">` с
`pointer-events: none`, чтобы клик доставался ссылке. Ленивая загрузка по
`IntersectionObserver`, кадр замирает; оживает по наведению и гаснет при уходе
курсора — тридцати трёх живых сцен разом не бывает. У полигонов на старом шелле
`tile: false`, и карточка остаётся текстовой.

Манифест пишется руками осознанно: тянуть названия механик из iframe через
`postMessage` — лишняя машинерия ради строки, которую всё равно пишешь, когда
полигон отработал.

В шапке самого полигона появляется ссылка назад на перечень.

## AGENTS.md

Раздел «Полигоны» переписывается в контракт: из чего состоит режим, что каркас
даёт даром, что цвет берётся из констант каркаса, что новый полигон — копия стаба
плюс файл с `MODES`, и что по итогам в `labs.js` дописывается строка. Отдельно
отмечается, что восемь первых полигонов пока на старом шелле.

В «Граблях» пункт про кэш сокращается: ручных версий у полигонов больше нет,
остаётся только `styles.css`.

## Проверка

Каркас нельзя оставить непроверенным до дня работы над И: ошибка в нём вскроется
в самый неподходящий момент. Поэтому на время работы рядом кладётся временный
полигон-проба с двумя простыми механиками — на нём вживую проверяются режимы,
инструменты, клавиши, пауза, покадровка, URL-состояние, переключение фона, снимок
и голый режим. После проверки проба удаляется; в репозиторий она не попадает.

Перечень проверяется на восьми текстовых карточках, плитка — на пробе с
`tile: true`.

Проверка идёт в браузере через превью, а не «должно работать».

## Порядок работ

1. `lab/lab.css` — шелл из существующих страниц плюс `[data-ground]` и голый режим.
2. `lab/lab.js` — каркас: загрузка файла буквы, режимы, инструменты, сцена, цикл.
3. Возможности каркаса: URL-состояние, фон, клавиши с паузой и покадровкой, PNG.
4. Проба, живая проверка всего перечисленного, удаление пробы.
5. `lab/labs.js` и `lab/index.html` с карточками и плиткой.
6. `AGENTS.md`.

## Риски

**Каркас без потребителя.** До буквы И на новом шелле не будет ни одного
настоящего полигона. Снимается пробой из пункта 4, но остаётся: настоящие
механики нагрузят каркас иначе, чем проба. Первая буква на каркасе почти наверняка
потребует правок — это нормально и заложено.

**Расхождение старого и нового.** Пока живут два поколения, правка каркаса не
доезжает до восьми старых полигонов. Осознанная плата за то, что рабочие файлы не
трогаем.

**Глобальная область.** Каркас складывает всё в глобальные имена, и файл буквы
может их затенить, объявив своё `S` или `line`. Полигон — стенд, и цена такой
ошибки — сломанная страница на локальной машине, поэтому защиты не строим, но
список занятых имён держим в AGENTS.md.
